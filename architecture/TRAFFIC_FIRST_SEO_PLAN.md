## Executive summary

The export contains **30,000 data rows**, **10,304 unique normalized keywords**, and **2,597,820 total source-derived search volume**. The controlled KalQLater taxonomy classifies **3,812 keywords / 1,291,070 volume as relevant** and **6,492 keywords / 1,306,750 volume as rejected**. Rejection is deliberately conservative: competitor navigation, medical/clinical intent, political or celebrity speculation, non-English queries in this EN rollout, standalone media-character demand, and unrelated article traffic do not become KalQLater pages.

The fastest traffic path is to strengthen existing type pages, the Compare hub/pairs, existing type-career guides, and live Insights tools before opening broad new programmatic families. The best new-page candidates are consolidated type character pages, careful famous-people pages, and a small number of high-demand MBTI explainers. Every intent family has one canonical owner.

The priority score is directional, not a ranking forecast: **35% normalized cluster traffic, 25% demand-adjusted KD advantage, 20% topical relevance/product usefulness, 10% existing-site leverage, and 10% implementation ease**. Traffic uses the square root of cluster volume relative to the largest relevant cluster; the KD advantage is discounted when demand is very small so low-KD/near-zero-volume terms cannot dominate a traffic-first queue. Scores are normalized to 0–100. Cluster volume sums deduplicated keyword rows; it is not estimated traffic.

## Cannibalization controls

1. One type head intent -> `/en/personality/{type}`.
2. One personality-career intent -> `/en/personality/{type}/careers`.
3. One ordered type pair -> existing `/en/compare/{canonical-pair}` regardless of query order.
4. Compatibility-chart overview -> `/en/compare`; type compatibility navigation is distinct and must link to pairs.
5. Famous people and celebrities -> one `/famous-people` URL per type.
6. Characters and fictional characters -> one `/characters` URL per type by default.
7. Reversed dimensions share one explainer.
8. Query variants never create pages solely because the wording changes.

Current collision risks are the Compare hub versus a future compatibility hub, core type pages versus character/famous terms they currently partially satisfy, `/en/careers` versus type-career guides, and Insights landings versus article-shaped quiz pages. Canonical ownership above resolves these without redirecting current URLs.
